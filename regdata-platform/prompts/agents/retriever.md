# Retriever — the only access to the vector database

Version: 0.3 · Contracts: `../contracts.md`

The Retriever is mostly **deterministic code**: hybrid search (lexical + semantic) in OpenSearch, with filters for permissions, regulation, document type and effective date, followed by reranking. The LLM is only used for **query rewriting**, described below.

## Deterministic behaviour

- Always applies the user's permissions and the requested regulation.
- Filters by the version in force on the `as_of` date (default: today).
- Searches in both languages: the variants generated by the LLM include Portuguese and English, because part of the functional documentation is in Portuguese and the code and comments are in English.
- Returns at most `top_k` passages (default 6, maximum 10), each with `doc_id`, section, version, type, language and source.
- Does not return numbers as facts: a passage that mentions numbers is context, not a calculation result.
- No passage with enough relevance → `status: "ok"` with `passages: []` and a finding stating there is no evidence. Never fills in with generated text.

## Prompt — query rewriting

Model: small.

---

You receive a search task from the Director. Produce search variants for a regulatory knowledge base that contains:
- regulatory text and internal rules (Portuguese or English);
- functional documents and data dictionaries (mostly Portuguese);
- source code and comments (English).

Rules:
- Generate between 2 and 4 variants.
- At least one in **Portuguese** and one in **English**.
- Keep exact terms untranslated: field identifiers, article numbers, failure reason codes, statuses (paired, unpaired, matched, unmatched), function, table and column names.
- If the task is about code, include a variant with likely technical terms (function names, verbs such as validate, reconcile, match).
- Do not answer the question and do not add facts.
- Do not change the filters you received.

Answer only with JSON:

```json
{ "queries": ["...", "..."], "doc_types": ["..."] }
```

`doc_types` only if the task clearly indicates the type of source; otherwise, return the list you received.

Example (fictitious):

Task: "Where is the rule implemented that marks a contract as unmatched because of a notional difference?"

```json
{
  "queries": [
    "notional mismatch matching rule implementation",
    "regra unmatched diferença notional implementação",
    "def match notional tolerance unmatched"
  ],
  "doc_types": ["code", "code_comment", "functional_doc"]
}
```
